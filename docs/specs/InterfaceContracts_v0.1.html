A Entry & cold-start

seed_verb_poolv1 · §5.0v1

Bootstrap a brand-new user with no verbs through micro-scenarios (one-verb situated moments) until the pool can operate a full scenario. Recognition-first; generation is the later destination.

OWNER: Learning-Content service · DEPENDS ON: micro-scenario corpus (authored once)

Precondition

verb_pool.size < seed_target (default seed_target = 20). If pool already seeded, this capability is a no-op and the agent should route to resolve_scenario.

Invoke · input 
user_id: "usr_..."
native_language: "en"     # for recognition-mode glosses
seed_target: 20           # core verbs to seed before full scenarios
Verify · output 
seeded_verbs: ["querer", "tener", "ir", ...]
micro_scenarios_completed: 18
mode: "recognition"      # NOT generation at true zero
pool_ready_for_full: true  # gate to exit cold-start
Verification checks
  • Every verb in seeded_verbs was introduced inside a micro-scenario — never as an isolated conjugation. (Charter non-goal: not a drill app.)
  • mode == "recognition" while pool is below target; generation is not required of the user here.
  • pool_ready_for_full == true only when seeded_verbs.length >= seed_target.
Failure modes
  • E_CORPUS_MISSING — no micro-scenario exists for a needed core verb. Block, do not fabricate at runtime.
  • E_FORCED_GENERATION — system demanded user-generation at zero state. Reject: violates §4.3 ramp.
resolve_scenariov1routes risk

Turn a user request (or a picked starter scenario) into a resolved scenario spec, and route it by stakes: high-stakes topics → vetted path, everyday → live path. This is the boundary where the #1 risk is governed.

OWNER: Scenario-Router service · CALLS: classify_stakes, then provision_scenario

Invoke · input 
user_id: "usr_..."
request: "I have a cita at the extranjería"
user_high_stakes_flag: false   # explicit user signal, optional
locale: "es-ES"                 # fixed in v1
Verify · output 
scenario_id: "scn_..."
title: "Immigration appointment (TIE pickup)"
stakes: "high"                 # high | everyday
route: "vetted"                # vetted | live
gating_verbs: ["recoger","presentar","esperar"]
missing_verbs: ["presentar"]   # not yet in pool → must drill
Verification checks
  • If topic ∈ {immigration, legal, medical, financial, housing-contract} OR user_high_stakes_flag → route == "vetted". No exceptions.
  • route == "live" permitted only when stakes == "everyday".
  • gating_verbs ⊆ the 100-verb set (Charter non-goal: no out-of-scope vocabulary).
Hard invariantA high-stakes scenario MUST NOT be served on the live path. Misroute here is the single most severe contract violation (Charter: "never generate consequential content unguarded").

B Content provision

provision_scenariov1

Materialize the resolved scenario's content (dialogue, prompts, audio) via the route chosen by resolve_scenario. Live = on-demand generation constrained to guardrails; vetted = validated phrasing layer + native-reviewed.

OWNER: Content-Runtime (live) / Content-Vetting (vetted) · GATED BY: route

Invoke · input 
scenario_id: "scn_..."
route: "live"                  # from resolve_scenario, not overridable
level: "beginner"
Verify · output 
dialogue: [{speaker:"cashier", text:"¿Quieres bolsa?"}, ...]
audio: {source:"tts", voice:"es-ES"}   # "produced" for vetted
phrasing_provenance: "live_guardrailed"      # or "validated_layer"
guardrail_passed: true
Verification checks
  • If input route == "vetted" → phrasing_provenance == "validated_layer" and a native-review stamp is present.
  • If route == "live" → guardrail_passed == true; on false, do not surface to user, emit flag.
  • Register/locale match es-ES; no invented procedures or institutions on the live path.
Failure modes
  • E_GUARDRAIL_FAIL — live generation produced inauthentic/risky phrasing. Suppress + log to guardrail_violation_rate metric.
  • E_ROUTE_OVERRIDE — caller attempted to force vetted content onto live path or vice-versa. Reject.
generate_curveballv1

Produce an off-script twist or small-talk turn for a scenario the user has already cleared — the engine behind ladder rungs 3–4. Inherently generative; cannot be pre-built.

OWNER: Content-Runtime · CONSTRAINED BY: scenario context + level

Invoke · input 
scenario_id: "scn_..."
current_rung: 2             # survived_solo → push toward 3/4
type: "small_talk"       # curveball | small_talk
Verify · output 
turn: "¿Qué tal la mañana?"
stays_in_scenario: true
level_appropriate: true
uses_pool_verbs_only: true
Verification checks
  • stays_in_scenario == true — a curveball is a twist, not a new topic.
  • Only offered when current_rung >= 2 (don't surprise a user still surviving the script).

C Practice

drill_verbsv1

Run the scaffold-and-fade production ladder for a scenario's gating verbs: card/tile assembly → word-bank → free typing, titrated to per-verb mastery. No multiple-choice recognition (that's a non-goal above the cold-start floor).

OWNER: Practice-Engine · READS/WRITES: verb mastery pool

Invoke · input 
user_id: "usr_..."
verbs: ["querer","pagar"]
forms: ["present","ir_a_future","preterite"]
persons: ["yo","tu","usted"]   # v1 scope only
Verify · output 
results: [{verb:"querer", input_mode:"typing", correct:true, latency_ms:2400}]
scaffold_level: "typing"   # tiles | word_bank | typing
mastery_delta: {"querer": +0.1}
Verification checks
  • forms ⊆ {present, ir_a_future, preterite} and persons ⊆ {yo, tú, usted} — v1 conjugation scope.
  • scaffold_level fades toward typing as mastery rises; never regresses to multiple-choice.
  • latency_ms recorded — feeds the "rapid retrieval" success metric.
rehearse_dialoguev1v1 · §4.5

Stakes-free, repeatable role-play of the full exchange with the AI partner. Doubles as the pre-mission confidence surface the anxious user needs before ever attempting reality (J4). Unlimited retries, no scoring.

OWNER: Content-Runtime (role-play) · NO real-world side effects

Invoke · input 
user_id: "usr_..."
scenario_id: "scn_..."
partner_mode: "forgiving"   # forgiving | natural_speed
Verify · output 
transcript: [...]
retries_used: 3            # unlimited by design
scored: false             # MUST be false — confidence, not assessment
confidence_signal: "rehearsed_confidently"  # pre-0 rung
Verification checks
  • scored == false always — rehearsal must never feel like a test (J4 churn risk).
  • Retries are unbounded; no penalty surfaces to the user.
  • May emit confidence_signal as a pre-mission rung but must not gate progress on a real mission.

D Outcome & progression

grade_missionv1

Capture the user's self-graded real-world outcome on the Competency Ladder, plus the "Were you understood?" comprehension signal. Includes an explicit not_yet option that is not failure (J4).

OWNER: Progression service · INPUT IS SELF-REPORT — never auto-verified in v1

Invoke · input 
user_id: "usr_..."
scenario_id: "scn_..."
rung: "survived_solo"
   # not_yet | froze | survived_with_phone | survived_solo |
   # handled_curveball | made_small_talk
understood: "repeated_once"  # first_try | repeated_once | not_understood
Verify · output 
accepted: true
rung_recorded: "survived_solo"
is_failure: false        # not_yet and froze are NOT scored as failure
trend: "up"               # confidence/trend signal, not a hard score
Verification checks
  • rung == "not_yet" → is_failure == false; routes user back to rehearse_dialogue, not a fail state.
  • understood treated as a noisy confidence signal — never a precise score, never app-side ASR in v1.
  • No geolocation or automated verification asserted — outcome is self-report by design.
update_ladder & update_verb_masteryv1

Persist progression: advance the scenario's ladder rung and fold drilled verbs into the shared mastery pool so the next resolve_scenario starts ahead, not from zero. This is the loop-back that makes effort compound.

OWNER: Progression service · WRITES: shared verb pool (global, cross-scenario)

Verify · output 
scenario_rung: "survived_solo"
pool_updated: [{verb:"pagar", mastery:0.7}]
carries_to_future_scenarios: true   # shared, not siloed
Verification checks
  • Mastery is global: a verb mastered in scenario A is available in scenario B. Never reset per-scenario.
  • A cleared scenario is NOT retired — it remains re-servable for ladder climbing (rungs 3–4).
Loop invariantupdate_verb_mastery output must feed the next resolve_scenario's missing_verbs calculation. If the pool doesn't compound across scenarios, the product's core promise is broken.
HOW TO COMPOSE → a full session = seed_verb_pool? → resolve_scenario → provision_scenario → drill_verbs → rehearse_dialogue → grade_mission → update_ladder + update_verb_mastery → loop. seed_verb_pool runs only on an empty pool; rehearse_dialogue is stakes-free/unscored and serves the pre-mission user, and grade_mission.not_yet is never failure. All are part of v1 (PRD v0.4 §5.0 / §4.5).
